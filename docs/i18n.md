# Translating Archyne

Archyne ships English, Spanish, Italian, German, Arabic, Simplified Chinese
and Japanese. Adding a locale is a single file plus two lines of registration.

## How it works

`src/i18n/en.ts` is the source catalogue and the only one in the initial
bundle. Every other locale is a lazily-imported module, so a user who never
switches language downloads nothing extra.

Catalogues are typed as `Messages`, which is derived from `en`. A missing or
misspelled key is a **compile error**, not a blank label at runtime.

## Adding a locale

1. Copy `src/i18n/en.ts` to `src/i18n/<code>.ts`, change the export to

   ```ts
   import type { Messages } from "./en";
   export const messages: Messages = { ... };
   ```

2. Register it in `src/i18n/index.ts` — add the code to the `Locale` union, an
   entry in `LOCALES` (its name **in its own language**, and its direction),
   and a loader in `LOADERS`.

3. Run `npm test`. `src/i18n/i18n.test.ts` checks every catalogue for missing
   keys, empty values, placeholder drift, and that the prose was actually
   translated rather than copied.

## Rules

**Keep placeholders identical.** `{name}`, `{count}` and friends are
substituted at runtime; dropping one produces a sentence that silently loses
its subject. Type checking cannot catch this, so the test suite does.

**Do not translate these**: `app.name` (the product name), `panel.tabCode`
(the Mermaid dialect), `export.formatPng` / `export.formatSvg` (file formats),
and the `(accTitle)` / `(accDescr)` fragments in the inspector labels — those
name literal Mermaid syntax the user has to type.

**Vendor icon categories** (AWS, Google, Azure…) are deliberately not in the
catalogue. They are brand names, and translating them would make icon search
harder rather than easier.

## Which locale the app starts in

English, always — until the user picks something else from the toolbar, which
is then remembered.

The app deliberately does **not** read `navigator.languages`. Sniffing the
browser means the interface changes language on its own the moment a new
catalogue ships: adding Italian silently flipped every Italian-configured
machine from English to Italian, with no action by the user. Locale is a
choice made once, not a property of the machine.

## Right-to-left

Setting `dir: "rtl"` in `LOCALES` is enough. `initI18n` writes `<html dir>`,
and the `[dir="rtl"]` rules in `src/styles.css` mirror the chrome: the palette
moves to the right, the side panel to the left, drawers slide from the
opposite edge.

Two things deliberately **stay** left-to-right:

- **The Mermaid source panel.** It is code, not prose.
- **The canvas.** A flowchart drawn left-to-right must not flip because the
  reader's UI language changed — the layout belongs to the diagram's author.
  Use the toolbar's Direction control to change a diagram's flow.

Overlay chrome inside the canvas (the context menu, the sequence editor) does
follow the UI direction.

**Anchor floating chrome with logical properties** — `inset-inline-end`, not
`right`. A panel anchored to the physical right edge opens off-screen in RTL,
because its trigger has moved to the opposite side. That once made the
language selector unreachable in Arabic, so the choice could not be undone.
`npm run test:e2e:rtl` checks this.

## What is not translated yet

- The `README`, `CONTRIBUTING` and other repository documentation
- Mermaid's own error messages, which surface in the code panel and come from
  the upstream parser
- Diagram content itself, which is the user's
